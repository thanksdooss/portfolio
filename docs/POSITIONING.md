# 포지셔닝 전략 — "김진녕"이라는 제품

이 사이트는 포트폴리오이자 랜딩 페이지다. 목표는 **읽히는 것이 아니라 기억되는 것**이다.

## 1. 구매자와 구매 상황

| 항목 | 내용 |
|---|---|
| 구매자 | SK 계열 채용연계 심사자 (DT 직무 / 기술영업) |
| 구매 상황 | 지원서 더미에서 5분 안에 "면접에서 볼 사람"을 고르는 순간 |
| 대체재 | 컴퓨터공학 전공 지원자 (코드 경험 많음), 기계공학 지원자 (AI 경험 없음) |
| 구매 저항 | "기계 전공인데 개발이 될까?", "중퇴인데 괜찮나?" |

## 2. 카테고리 선점

기존 카테고리에서 2등을 하지 말고, 새 카테고리에서 1등을 한다.

> **현장을 읽을 수 있는 AI 엔지니어.**
> 도면과 규정을 읽고, 모델을 만들고, 현장의 말로 설명하는 사람.

- CS 전공자와 코딩 실력으로 겨루지 않는다. **도면·규정·공정을 읽는 능력**이 차별점이다.
- 기계 전공자와 설계 실력으로 겨루지 않는다. **직접 만들어 배포한 결과물**이 차별점이다.
- 약점(중퇴)은 숨기지 않고 **선택의 결과**로 제시한다. "취업 연계에 전념하려고 자퇴했다"는 문장 하나로 리스크를 의지로 바꾼다.

## 3. 메시지 구조 — 3초 / 30초 / 3분

심사자는 세 단계로 읽는다. 각 단계에 화면을 하나씩 대응시킨다.

| 단계 | 질문 | 화면 | 담는 것 |
|---|---|---|---|
| 3초 | 이 사람 뭐 하는 사람? | 첫 화면 | 한 줄 정체성 + 선도 애니메이션. 문장은 최소로 |
| 30초 | 진짜야? 근거는? | 철학 + 숫자 띠 + 대표작 | 수상·수치 4개, 작품당 한 화면 |
| 3분 | 어떻게 일하는 사람? | 케이스 스터디 | 문제 → 접근 → 내 역할 → 결과 |

**원칙: 한 화면에 메시지 하나.** 설명을 늘리는 대신 화면 전환으로 기억시킨다.

## 4. 근거 자산 (증빙이 있는 것만)

| 주장 | 근거 |
|---|---|
| 현장이 인정했다 | HD현대이엔티 대표이사 우수상 |
| 설득할 수 있다 | 해커톤 대상(팀장·발표), 부스 설명 이해도 4.5/5 (83명) |
| 직접 만든다 | 배포된 서비스 2종, 로컬 LLM 도구 3종, PLC→Unity 파이프라인 |
| 기본기가 있다 | 평점 4.46/4.5, 기계설계기사, AICE Basic 100점 |

## 5. 신뢰 전략

과장하지 않는 것이 이 사이트의 가장 강한 마케팅이다.

- 팀 성과와 개인 기여를 구분해 적는다 (예: 인덱스 튜닝 94.4%는 "팀 과제"로 명시).
- 오픈소스·강사 템플릿 사용은 케이스마다 "밝혀 둘 점"에 적는다.
- 증빙이 없는 수상은 아예 싣지 않는다.
- → 심사자가 한 번이라도 "이건 부풀렸네"라고 느끼면 전체가 무너진다. 그 리스크를 0으로 만든다.

## 6. 전환 설계 (CTA)

- 주 행동 하나: **이메일 연락**. 나머지는 보조.
- 대표작을 지나 아래로 내려온 방문자에게만 작은 연락 버튼을 띄운다(관심을 보인 사람에게만).
- PDF 요약본은 "지원서에 첨부할 파일"로 항상 한 번의 클릭 거리에 둔다.

## 7. 채널별 첫인상 일치

지원처마다 다른 경로로 들어오지만 첫 문장은 같아야 한다.

| 채널 | 첫인상 | 관리 파일 |
|---|---|---|
| 카카오톡·링크 공유 | OG 이미지의 한 줄 | `public/og.png` |
| 지원서 첨부 | PDF 첫 줄 | `#/print` |
| GitHub 유입 | 저장소 README | `README.md` |
| 직무별 링크 | 트랙 문구 | `src/config/site.config.js` (`?track=sales`) |

## 8. 하지 않을 것

- 모든 활동을 첫 화면에 늘어놓는 것 (아카이브로 내린다)
- 문장으로 설명을 덧붙이는 것 (화면 전환과 수치로 대신한다)
- 남의 성과를 내 것처럼 쓰는 것
- 학교·학번·개인정보 노출 (배포 때마다 자동 검사)
